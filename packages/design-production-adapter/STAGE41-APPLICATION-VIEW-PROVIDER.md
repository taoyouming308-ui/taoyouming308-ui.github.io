# Application-image comparison/synthesis provider (offline only)

## Explicit new lane

Provider intent v8 consumes strict input v3; it does not broaden the Stage40 v7
before-only intent or rewrite historical hashes. Candidate v6 records synthetic
mock model or synthetic deterministic generation. Both synthetic source kinds
use `system`, never an actual model or employee attribution. Prepared/full v7
and managed history v5 preserve old versions and journal authors.

Comparison requires two distinct before/after task, source request/media/manifest,
processing claim/artifact and normalized manifest references, with the same
angle and current authority. Actual processing request IDs are also distinct.
Equal content hashes are allowed: different immutable records do not prove
separate physical captures. It is never a process, recipe or outcome inference.

Synthesis requires at least one already accepted new comparison. It reconstructs
exact historical adoption and confirmation evidence. Missing views and conflicts
remain explicit. Zero/one allowed review-focus choice uses deterministic server
selection, with no key, fee approval or model send. Multiple choices use only a
mock model selecting a permitted finite choice; raw photographs are not resent.
Neither acceptance nor synthesis confirms an employee's original judgment.

## Durable authorization

The original provider attempts, context, issued approvals and approval tables
are reused. Independent processing/cost/approval issuers use existing
`design_managed_model_*_issuer` roles and the existing managed-view permissions
table. They are not browser routes. The owner/request namespace prevents a new
lane from bypassing an existing request claim. Lost dispatch/commit receipts
remain uncertain; query the same request and never automatically resend.

Current identity, personal key revision, exact workflow and all source/ancestor
rights are rechecked. No authorization cache or absolute physical-commit-time
claim is introduced. Runtime inherited-author/regrant use remains closed even
though pure history preserves original authors.

## SQL installation boundary

In an existing isolated Stage40 test database, install provider-binding,
ancestor-helper, result-helper, then the root-owned workflow fixture. All use
Stage41 filenames and synthetic-database guards. They do not install themselves.

The ancestor reader is a fixed private SECURITY DEFINER function owned by the
existing managed-normalized-workflow capability. Only identity capability gets
EXECUTE. Runtime/issuers/public roles get neither direct EXECUTE nor table
access. It checks current authority/scope, exact consumed comparison ID and
receipt digest and returns at most 1 MiB. This does not modify old table ACLs.

## Verification scope

Pure tests exercise real contracts/preparer/dispatcher with mock SQL, object and
model services, including local synthesis, finite model synthesis, late revoke,
lost claim COMMIT, replay, isolated v8 repository flags, minimum browser DTO and
post-publication auth failures. Placeholder PNG-signature fixture bytes are not
codec or arbitrary-photo verification. Actual PG/worker/browser verification is
owned and reported separately; pure tests do not establish it.

Stage41 service errors after dispatch/publication use typed uncertainty. Older
Stage40 application/normalized service generic errors are unchanged in this
stage; their browser recovery remains conservative query-only. All production,
real credentials, real customer media and paid sends stay disabled.

# Stage 30: managed multi-view review (work in progress)

## Scope and independent activation

The new managed-view feature is separately disabled by default. It adds per-angle before observations, exact same-angle before/after comparisons, and a synthesis of accepted comparison evidence. It is not a production enablement, deployment, migration, or statement of real model quality. Synthetic test assertions are not customer case counts.

Original private source/derivative versions, verification evidence, workflow revision, immutable employee authority, and the existing provider request/approval ledger remain bound. Image request v5 shares the existing send ledger; workflow sidecars only hold candidates and adoption receipts. Old v4 requests and old archives remain separate and readable.

Synthesis never resends images. Zero or one permitted review-focus choice is deterministic and does not require a provider key or paid transport. More choices require a separately approved model request. Missing angles, non-comparable evidence, contradictions, and employee-confirmation status remain explicit. Image observations are not evidence of actual chemical formula, technique, causality, or success.

## Deliberate limits

- Reported route/browser latency is from the bounded synthetic visit and mock transport. It is not a real-provider latency or long-history performance guarantee. The 30-second client limit has not been raised.
- The existing 1 MiB request limit is unchanged. Oversized image pairs reject without automatic resizing, transformation, new approval, or resend.
- Both legacy history-v1 and history-v2 JavaScript contracts permit at most 300 input records and 1,000 accepted results. The older SQL-only validator permitted 1,000 inputs, but a 301-input record is not valid under the original full application contract. Over-limit data rejects without truncation; this is not claimed as a successful compatibility upgrade.
- Candidate sidecar `manifest_id` is provenance, not a separate assertion that publication and consumption use one identical manifest. Live authorization and authorship verification remain in the existing read-bundle/operation-author path. Do not claim stronger manifest equality.
- Current authorized full snapshot responses still include private provenance metadata. Minimal new view DTOs do not imply full-snapshot HTTP minimization.
- Unknown send outcomes permit original-ID status lookup, not automatic resend. No authorization cache or TTL extension is introduced.

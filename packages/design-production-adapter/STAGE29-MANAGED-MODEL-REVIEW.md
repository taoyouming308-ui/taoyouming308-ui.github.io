# Stage29: managed model result → original workflow (offline)

## Implemented boundary

A separately enabled `managedModel` configuration composes the verified private byte reader, bounded single-before-view request, current personal key, independent processing/cost/combined issuer receipts and the **original** durable provider request ledger. No model, key, network transport or approval is chosen implicitly. Existing v1–v3 provider modes reject v4; a reused owner/request key cannot escape old ledger tombstones.

`managed-model/describe`, `status`, `load` expose minimal projected responses. Unknown sends are queried by the same ID, never automatically retried. A completed response is published to an immutable candidate sidecar, not another sending ledger. Selection submits candidate ID and indices only. The existing workflow appends unconfirmed model observations; a separate employee `confirm_entry` retains its own original words. Perm/dye technique, maintenance, measurements and actual execution are not inferred from this image.

The v3 record and full archive preserve old photoRefs/modelCandidates/legacy versions, add private source/derivative/task/report/candidate/acceptance lineage, and replay mixed native history. Actual original workflow digests and author/manifest rows are checked in the repository. Full v3 saving requires a separate live history verification callback. The authorized full snapshot protocol still includes private provenance metadata; renderer redaction is **not** HTTP data minimization. New minimal endpoints never return object locators or sealed keys.

## Transaction / authorization design

Same-connection fixed capabilities copy only the exact completed shared-ledger result, reconstruct the finite native additions, CAS the original workflow and consume the candidate atomically. After head advancement, a transaction-ID/exact-head consumption proof permits only that old→new workflow transition; key, source, verified task, identity and processing/cost receipts still receive fresh checks. Arbitrary callers cannot invoke the private retained-context capability. This is not an absolute wall-clock-at-COMMIT guarantee and does not remove previously documented transaction-lifetime limitations.

Historical accepted records use immutable consumed evidence and current original scope/author/manifest access, not renewed permission to send or an expired old fee receipt. Raw old write entry points may not inject/drop/rewrite the new lane. No old identity data is automatically migrated.

### 已观察的真实查询

1. `bill!bill.action?set=null`、`billFlag=0`：现有完整分页项目消费清单，校验门店、日期、筛选、数量。
2. `bill!detail.action`：multipart `jsonObj` + `shopid`，取单据、支付、项目与员工分配。逐单核对 `id/shopid/consumetime`。只读，不调用开单、收款、退款或重算接口。
3. `report!shopSumDay.action`：源页面 `MGJ_reservation/report_shopSumDay.html`、`js/report_shopSumDay.js`、`js/api.js` 证明的查询接口。表单 `jsonObj` + `shopid`；含 parentShopId、会话 shopId、目标 shopIds、period、incomeType、depcode。period 模仿源页面 ISO 日期的 UTC 毫秒，不擅自替换为北京时间午夜。
4. incomeType：1 项目、2 卖品、3 开/充卡、4 套餐销售、5 年卡销售。日汇总区分现金类、划卡类、其他非现类；不是员工逐项目凭证。

日汇总不回显门店，诊断输出明确标记 `request_only`，不能单独证明门店完整性。两店 1/1 差异样本与已校验门店的项目快照交叉一致；实际营业金额仅在本轮私有核验中使用，不写入公共代码文档。此证据不是全年所有类别验证。

向里造型 1/1—1/7 样本中，6 张已有已确认日报的 cash_flow 与非空支付宝/微信/点评分项均匹配；1/5 未返回行，**不得填零或推断停业**。该周项目和全类别汇总相同，尚未证明发生充值、退款、卡金核销时的分类规则。

### 防止重复计账

- 同一项目实测有技师、设计师各自计入完整金额的岗位业绩分配；支付投影 cashList 两行相加也会翻倍。它们不是两笔门店收入。
- 员工匹配使用 `empfees.empid` 与 `empList.empId` 等明确别名，不能把分配行 `id` 当员工 ID。别名冲突拒绝猜测。
- 支付真实拆分读 `paydetail`；不汇总岗位 cashList/cardList 作为收入，不按多个支付筛选分别加账单总额。
- 当前配置把 OTHERFEE2 标为抖音、OTHERFEE1 标为口碑；当前配置不是全年历史配置未变的证明。
- 当前月报从已确认日报 `payment.cash_flow` 读取营业收入。不能把包含充值、套餐销售的全业务现金类总额直接写到该字段。
- 对公/对私、技师金额/次数、基础/技术分类、渠道和项目重叠、售卡/核销/退款须有明确规则；未知留缺口，不能自行分摊、按姓名或关键词猜财务分类。

## 本轮诊断工具

`scripts/audit_mgj_daily_report_source.py` 只读、非同步器：固定两店、2026 年、不接受未来日期；每次最多 3 张账单或 1 个店日汇总，最多 60 秒，共用消费锁。失败关闭，不自动重试登录、不改变正常同步频率。

```sh
/usr/bin/python3 scripts/audit_mgj_daily_report_source.py --shop 1837032 --date 2026-01-01 --bill-limit 3
/usr/bin/python3 scripts/audit_mgj_daily_report_source.py --shop 1837032 --date 2026-01-01 --daily-summary --summary-scope projects
/usr/bin/python3 -m unittest scripts.test_audit_mgj_daily_report_source -v
```

cookies 只从既有配置读取，经 curl stdin 传递，不出现在 argv、输出、Git；TLS 校验不关闭。诊断输出剔除客户姓名、手机号及完整员工对象。真实原始快照不得提交公共代码仓库。

汇总金额使用 Decimal 转整数分，表头与分组改变、重复/错日期、无行、负数或非整分拒绝；负数拒绝表示该工具尚不支持退款，不表示退款不存在。空字符串保留 null；组内有未知项时不声称对账成功。合成用例通过不等于生产全量完成。

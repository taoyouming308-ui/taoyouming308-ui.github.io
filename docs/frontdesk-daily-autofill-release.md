## 实际 SQL 及影响

候选迁移：`supabase/migrations/20260928005448_zysyr_frontdesk_daily_autofill.sql`。

- 草稿创建者/更新者及格子更新者允许 NULL，明确表示服务任务，不冒用任何财务账号；空创建者仅允许 `frontdesk-autofill` 来源。保留原用户 FK、财务身份校验及确认函数。
- 来源方法追加 `frontdesk_autofill`；原方法仍可读。新草稿固定 `zysyr_frontdesk_project_draft` 版式标记，仅这些草稿显示技师烫、染、护三列次数；旧版式和已确认表不变。
- 新增强制 RLS、客户端/服务角色无直接表权限的 `zysyr_daily_autofill_events`、`zysyr_daily_autofill_status`。前者留存不可更改的来源关联、完整修改前后格子和服务审计；后者为运行状态，不是账务。
- `mgj_autofill_daily_sheet` 仅服务角色可执行，固定公司、两家门店、2026 年及非未来日期。读取同一私有收银快照，并重新比对当前源列表；不接收客户端提供的金额或任意格子。
- 已确认、锁账、带原图、多个草稿、已人工填写的非自动草稿全部让开。仅完整核验为空的手工模板可被替换，472 格原样保存进不可更改的审计后，才移除空占位格。自动草稿里的人工金额、显式留空、备注和姓名修改保持不变。
- 采用稳定员工 ID/岗位键，新增员工排序不会把人工修改转给另一人。同一最新快照重试不增草稿/版本；A→B→A 的实际来源更正可以重新应用。来源撤销的自动数字清空，不保留过期数值。
- 私有来源 head 更新触发自动填写，没有新增美管加请求/轮询/定时器。草稿错误独立记录 SQLSTATE，回滚该草稿子事务，正常收银快照仍接受；没有无限重试。
- 不调用入账、收入、月报、凭证审核或账务调整函数，不更改原图、财务账户/RLS 或既有确认路径。电子凭证替代纸图的最终确认桥接仍是独立后续模块。

## 填写口径与留空

按源员工分配业绩，不用项目标价替代业绩。单一且完整可验证的点评/抖音付款单进入平台业绩栏，不再重复计入项目栏；平台混合付款不猜拆分。向里 1/1 标准真实只读对照：已知洗剪吹、造型、烫发、点评、员工总业绩及支付栏目投影一致。真实金额不发布到公开源码；该对照不是全年验证。

技师只填源整数项目数的烫、染、护，未分类项目/缺次数保持未知。新老客数、售卡、零售、退款、全业务总额、现金流和卡金消费未取得完整口径，仍留空；现阶段不能将项目业绩总和当作全店收入。四个公/私账号渠道按既定要求不自动填写。黄格和页面提示明确待核对，`automatic_posting_enabled=false`，不冒充完整财务日报。

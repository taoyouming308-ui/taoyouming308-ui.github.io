## 全面投入使用前仍需处理

1. **P1，多人／多端并发编辑同一日报。** 保存接口有行锁，但未携带客户端期望修订号；旧页面仍可能覆盖新页面同一格的修改。核对回读到最终确认之间，也未绑定用户核对的版本号。当前窗口防连点不等于跨窗口乐观锁。全面多端上线前应补充保存／确认的版本冲突检测与双会话回归；现阶段不要同时编辑同一日报。
2. **P1，数据库与原图恢复演练。** scripts/backup-zysyr.sh 备份的是工程文件，不等于生产数据库及 Storage 原图的完整灾备。本轮没有完成生产备份恢复演练，不能承诺恢复点或恢复时间。需核验 Supabase 备份保留策略并在隔离环境恢复数据库及原图索引／对象。
3. **P2，零收入／休息日规则。** 当前前后端都要求员工收入大于 0；零营业额日报不能用普通入账流程完成。需明确“休息日无需日报”还是“零收入也应正式确认”，不能通过伪造金额绕过。
4. **P2，真实设备及实际账号验收。** 需财务用实际账号在手机、iPad Safari、电脑各验一张日报，检查键盘输入、横竖屏、双指放大、保存后重开、明确入账、月历和月报一致。代理未使用真实财务记录做写入演练。
5. **P2，历史完整性。** 机器草稿不能视为已入账；有原图关联不等于原图已人工核对。对尚无原图的空白草稿确认是否休息日或需要补资料，不生成或猜测缺失金额。
6. **项目级安全与性能待办。** 报表范围权限风险已收紧，但同一 Supabase 项目的 7 张非 zysyr 旧模块表仍被 Advisor 报告未启用 RLS，需其所属 App 单独评估，未擅自改动。Auth 泄露密码保护仍未开启。性能 Advisor 还有未索引外键等 INFO 提示，未做并发压测；低数据量回归通过不代表高负载容量已验证。

参考：[RLS 风险说明](https://supabase.com/docs/guides/database/database-linter?lint=0013_rls_disabled_in_public)、[内部 RPC 权限](https://supabase.com/docs/guides/database/functions#function-privileges)、[泄露密码保护](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。

## 财务验收步骤

1. 确认草稿已保存后再更新页面；不要在未保存时强制刷新。
2. 打开原日报，先核对少数仍残留的旧识别格，无须整张重新填写。
3. 点击保存草稿，退出再打开，确认空白和修改都保持；此时月历应显示草稿已保存、待入账。
4. 对照原图核对后点击入账，检查成功提示与已入账状态；重开后仍应保持已入账。
5. 检查该日金额和月报美发收入累计一致；不要在月报重复录入同一笔收入。

旧版本未记录成功的清空动作不能靠后台推断补写。本次不修改历史金额或候选状态，仍由财务对照原图确认。

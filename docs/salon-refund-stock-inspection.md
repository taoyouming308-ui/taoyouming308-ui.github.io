# 退款商品实物验收

状态：仅 `feature/meiguanjia-parity-v1` 本机合成数据；未部署、未应用任何远端数据库、未连接真实支付渠道。

## 规则

- 仅已批准退款申请的商品行可以验收。每行记录申请数量、可返库数量、商品状况、说明、员工、时间与版本；验收记录追加保存，不覆盖旧记录。
- 打开退款详情可看到最近验收并追加修订。提交携带当前验收版本，旧页面/并发编辑不能静默覆盖新记录。丢包/刷新恢复只保存请求号，并按本人、组织和门店范围只读核对原回执。
- 商品状况为“破损/瑕疵”或“不可再售”时，可返库数量必须为零；否则不能入回可售库存。批准后仍需每一商品行都有完整的最新验收记录，退款执行才可继续。
- 执行时仅把最新验收的可返库数量写入库存流水；未验收商品阻断整笔执行。实物验收本身不退款、不改订单金额、会员余额、库存余额或员工绩效。
- 资金退款回执与实物处理是两个独立证据链。本批没有增加实际支付渠道退款确认，也没有开放退款执行按钮；批准或验收都不代表顾客已收到退款。

## 验收

- 临时 PostgreSQL 与 Chrome 回归覆盖已批准门槛、逐项验收、0.500 部分可售入库、未验收执行拒绝且无副作用、修订留档、陈旧版本拒绝、幂等回执、权限隔离以及手机/桌面页面。
- 退款详情继续展示撤回字段；既有审批、撤回和请求恢复回归通过。
- Supabase 函数使用 `SECURITY INVOKER`、空 `search_path`、service_role-only 入口；表开启 RLS，anon/authenticated 无权限。参考 [Supabase 数据库函数安全指南](https://supabase.com/docs/guides/database/functions)。

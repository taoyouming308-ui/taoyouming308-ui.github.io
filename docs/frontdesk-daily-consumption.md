# 前台每日消费快照

## 修复原因与口径（2026-09-27）

旧 dashboard 用 `mgj_service_records` 汇总。该表是发质表的烫/染/护理核对投影，来自分批客户历史补档，不是完整营业流水。v575 的手机号去重没有修复源数据缺口。

新源为美管加营业记录 → 项目消费：`POST /shair/bill!bill.action?set=null` 的只读列表查询（实际页面表单及返回已核验），使用独立历史会话，不调用任何修改/销单/收银接口。

- `billFlag=0`、`bill.type=-1`：普通项目、套餐核销、年卡核销；不包括卖品销售、充值售卡、套餐销售。
- 金额：每个水单的「入账」`billEafeeEdit`，不是员工项目业绩之和，也不是现金实收。免单/零入账核销仍计入单数。
- 单数按源账单 ID；人数按完整非空手机号去重，无手机号单数单独提示。多笔单不是多位不同顾客。
- 本次 22 点只读实测：自由手艺人 24 笔、24 个手机号、项目入账 6500；向里造型 31 笔、29 个手机号、1 笔无手机号、项目入账 9628。此为该时点快照，不是未来固定值。

## 数据边界

`mgj_daily_consumption` 按 `(shop_name,business_date)` 私有存完整快照。RLS 开启，匿名/普通 Supabase authenticated 均无权限。前台沿用内部 session 和门店过滤，跨店客户档案共享不会放开此统计。

`mgj-customer-sync` 新增固定 `daily_consumption_write` 操作：原 Ed25519 签名域、时戳验证、两店白名单、近 31 天范围、完整条数/ID/金额/门店/日期校验。唯一 RPC 原子替换目标店日，拒绝旧 fetched_at 覆盖新快照。未改变 `bookings`、`customer_profiles`、原核对表或财务业务表。

解析失败、缺页、重复页、日期/门店回显不符、HTTP 错误均不上传，保留旧快照。完整且明确的 0 笔才能写空快照。超过 1000 单拒绝而非截断。

## 调度与部署

复用现有每分钟预约任务，在预约任务结束后运行消费模块，独立锁和 45 秒预算，按店日保存 5 分钟成功间隔；昨日每日补读一次。预约保留自身 55 秒预算与状态。消费失败不回滚预约；源 401/403/429 冷却 15 分钟，其他失败退避 5 分钟；不重登、不重置主会话，不增加另一套定时器。

`scripts/deploy_mgj_sync_runtime.sh --core-only` 先备份，依次安装签名客户端、消费模块、原同步模块及健康检查，逐文件哈希核验。状态：`~/.hermes/mgj_daily_consumption_status.json`。前台轮询自有云端 30 秒，不直接请求美管加。Mac 休眠/断网时无法同步，15 分钟后提示旧数据；没有历史快照的日期显示待同步，不冒充 0。

发布次序：测试 → 私有快照迁移 → 签名 writer → 有限真实同步和云端核对 → dashboard reader → Pages/运行脚本 → 自动轮验证。部署只列指定两个 Edge，不部署其他业务模块。源码、Edge、运行副本、Pages/CI 状态分别记录。

- 有限命令：`/usr/bin/python3 scripts/backfill_mgj_daily_consumption_2026.py --max-groups 80 --budget-seconds 1800`。每组间隔 2 秒，逐笔快照写入间隔 0.2 秒，独立任务锁并与日常消费共享源锁；日常消费已超过 4 分钟时先让出执行机会。锁冲突有界等待，超时/失败停止并保留进度，不自行重登、不创建新定时器、不无限循环。
- 检查点 `~/.hermes/mgj_daily_consumption_backfill_2026.json` 原子写入且权限 600；只记录日期、门店、单数、金额分和账单 ID 摘要，不落地客户资料或凭证。回执成功才记完成，重启跳过已成功店日。结束后必须按店日核对云端单数、金额分、ID 摘要，验证 270 天 × 2 店均存在，再报告补齐。
- 历史统计保留读取时间，但不套用当天 15 分钟新鲜度阈值。消费入账不等于现金实收，也不代表历史预约已补齐；未同步的旧预约不能凭消费账单伪造。

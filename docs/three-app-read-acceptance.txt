三端只读提速 · v690 候选验收

范围与正确性
  预约、前台当天、月报、日报：正常入口启动读取；摘要不是当前结果。实时鉴权
  后再核实变化；提示不可用、版本不对或无法应用差异时，保留原来的完整读取路径。
  自由手艺人：需要时再请求 AI、档案和展开的设计；发质编号查询只取编号，
  不再为取编号而把整个表单传回。训练聊天仅追加新消息；恢复或修改旧内容时重绘。
  前台：搜索、营业明细合并相同在途读取；原图按打开的档案读取。换人、换店、
  退出、撤权或作废时不能把迟到的结果显示给当前用户。
  报表：工资、备用金、凭证与来源候选只在当前门店/月/角色下合并在途读。
  刷新不得覆盖未提交的编辑；旧原图预览不能写回新月份。工资和凭证不落磁盘缓存。
  三端共用的离线静态包仅收录公开界面文件。更新时用新清单的 SHA-256 和类型
  核实旧文件；只要一个新文件未核实，就继续用原版，不强刷进行中的表单。
  不做离线收银、入账或重放提交，不更改任何历史记录、金额、原图或数据库结构。
  不变数据的响应可能很小，不代表服务器不用做权限核对、数据库查询或摘要计算。

对照方法与第一轮结果（合成数据，不是门店服务指标）
  基线为受保护 main 的 v689（1b70a903）。两个版本均走普通入口。

复核与发布顺序
  1. node scripts/build-app-shell.js --check，node scripts/test-salon-sync-regressions.js。
     在隔离环境运行完整 .githooks/pre-push，包括原有写入/原件/撤销/锁账回归。
  2. 运行 STARTUP_BROWSER=webkit node scripts/test-app-shell-browser.js，同时保留 Chromium
     结果。可用 BENCH_BASE=<v689工作树> BENCH_NORMAL_ENTRY=1 BENCH_REPS=3
     node scripts/test-scoped-read-benchmark.cjs 复测表格。模拟器不是实机。
  3. 实体 iPhone Safari 和桌面图标各试一次：冷/热打开、切日/月/店/账号、
     撤权、网络中断再恢复、打开/关闭原图、双设备作废、编辑中刷新/升级。
     使用非生产样本；核对原图内容和草稿。若无设备，不判定真机通过。
  4. 确认受保护 PR 精确提交的 CI；在不更改默认业务写入的前提下，先部署向后兼容的
     两个只读 Edge 更新，验鉴权、旧客户端响应及源码哈希；再正常合并前端。
     核对远程合并提交、Pages 部署及三入口/脚本字节；不以 push 或任务启动代替上线。
  5. 如异常，先切回完整读取（对受支持普通读路径可用 ?read_preview=0），
     档案详情等新投影有独立旧客户端兼容路径；该开关不等于全版本回滚。
     整版回滚用更高版本恢复上一个受保护提交的界面/静态包和对应函数源码。
     不回滚业务库，不删设备草稿，不强制重载正在编辑的页面。

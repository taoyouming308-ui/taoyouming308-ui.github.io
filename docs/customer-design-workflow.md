# 顾客设计思路档案

设计思路按顾客和每次服务归档，支持 ChatGPT 协作与员工手动填写。两种来源使用相同的八步结构，保留原始判断、优化方案、调整理由、照片和每次保存时的状态。

## 员工端使用

从预约或顾客档案打开“查看方案”，进入“设计思路”。最新一次服务与最新保存版本优先展示，其他服务日期和历史版本可展开。

“记录设计”用于新增保存版本：

1. 核对顾客、预约和服务日期。无预约的手动记录使用明确的服务日期。
2. 上传原始照片，分别标注正面、背面、左侧或右侧。完成照片和参考图另行标注。
3. 填写整体轮廓、发根毛流方向，以及八步初始判断。
4. 沟通后填写优化方案；发生变化的项目说明调整理由。
5. 选择本次状态并保存。保存成功后新增版本，旧版本和旧照片继续保留。

没有使用 ChatGPT 的员工可以完成全部填写、上传和保存操作。记录人取自服务端验证的员工会话，来源显示为员工手动填写。

## 八步对照

| 顺序 | 项目 | 记录边界 |
| --- | --- | --- |
| 1 | 风格 | 当前视觉表达、顾客希望的感觉及最终选择 |
| 2 | 人物 | 可见曲直与视觉量感、现场补充条件；不从照片推断内在性格 |
| 3 | 长度 | 当前长度、目标落点与需要保留的生活功能 |
| 4 | 发型特点 | 目标轮廓、体积、重量与区域任务 |
| 5 | 层次 | 重量和支撑的调整，表层覆盖与连接 |
| 6 | 刘海 | 方向、边缘、长短、厚薄、露眼程度和脸周连接 |
| 7 | 卷度 | C/S视觉曲线、质感、分布及尚未确认的工艺条件 |
| 8 | 打理 | 顾客可以完成的手法、所需时间与后续维护 |

整体轮廓和发根毛流方向位于八步之前，分别呈现初始判断与优化方案。每一步均展示初始判断、优化方案和调整理由；未确认的信息保持待补，不填成已完成事实。

## 照片与历史

- 原始照片、完成照片和参考图分别展示，点开查看原图。
- 上传保留原文件字节，不把压缩预览冒充原图；文件摘要用于回读核对。
- 每次保存记录操作人、来源、时间、服务日期和当次状态。
- 初始判断、优化中、方案确认、服务完成和回访均为独立版本。
- 在当前版本移出一张照片不会删除旧版本对该照片的引用。
- 新一次到店增加服务记录；同一次服务继续调整增加版本。

## ChatGPT 协作

发型师提供预约日期和时间后，通过预约文字信息和稳定客户编号定位档案。照片用于发型分析，不用于确认顾客身份。

ChatGPT 保存原始判断与后续讨论，不把现场无关闲聊整理入档。设计摘要、八步对照、调整理由和原始图片通过受保护的导入流程追加到同一结构；来源显示为 ChatGPT 协作。ChatGPT 档案链接可作为来源保留，链接本身不授予其他员工访问权限。

导入流程见 [受保护导入工具](customer-design-import.md)。客户资料、照片、短期令牌与导入进度必须保存在仓库之外，不能进入公开 Git 历史。

## 保存与冲突

保存以服务记录的最新版本作为并发前提。若其他人已保存新版本，保留当前草稿和已选照片，先读取新记录并核对，再由员工保存下一版。网络返回不明确时不自动重复写入；恢复时沿用同一请求标识，避免重复版本或重复照片。

设计写入必须核对实际顾客、门店及预约关联。“全部门店”仅是读取范围，不授予跨门店写入权限。原有预约备注、套餐、消费记录和同步规则保持各自用途，设计档案不写成消费或烫染诊断记录。

## 发布验证

发布前使用模拟顾客验证照片、八步对照、员工填写、历史版本、并发、失败恢复和跨门店拒绝。按兼容顺序部署新增数据库对象、受保护接口和员工端静态资源，通过仓库发布检查后核对线上版本。

真实顾客档案导入属于独立的数据操作，完成后核对顾客编号、预约、版本数量、来源、状态和原始照片摘要。代码发布不自动更改预约状态、消费或其他门店数据，也不强制刷新正在工作的员工。

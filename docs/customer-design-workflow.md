# 顾客设计思路档案

设计思路按顾客和每次服务归档，支持 ChatGPT 协作与员工手动填写。统一使用“剪烫十大流程统筹、八步人物设计定方向、六区执行落地、完成照片复盘”的结构，保留原始判断、优化方案、调整理由、执行记录、照片和每次保存时的状态。

## 员工端使用

从预约、顾客档案或已关联顾客与本次服务的发质分析表进入“设计思路”。入口引用同一顾客、同一次服务的设计档案，不把设计另存为发质表中的第二份副本。

最新一次服务优先展开。每次服务只展示一个当前方案：优先选最新已确认、已完成或回访记录；没有这类记录时选最新初始判断或优化中记录。历次到店仍可查看，中间更新不逐版铺在现场页面，旧版本和旧照片在后台完整保留。继续编辑时以真正最新保存版本核对并发，不能用当前展示版本绕过后续更新。

“记录设计”用于新增保存版本：

1. 核对顾客、预约和服务日期。无预约的手动记录使用明确的服务日期。
2. 上传原始照片，分别标注正面、背面、左侧或右侧。完成照片和参考图另行标注。
3. 填写整体轮廓、发根毛流方向，以及八步初始判断。
4. 沟通后填写优化方案；发生变化的项目说明调整理由。
5. 按六区记录当前问题、目标、具体怎么做和完成核对点；十大流程按本次实际项目选填。
6. 完成后上传实际效果、记录已达成、待调整和下次重点，选择本次状态并保存。保存成功后新增版本，旧版本和旧照片继续保留。

没有使用 ChatGPT 的员工可以完成全部填写、上传和保存操作。记录人取自服务端验证的员工会话，来源显示为员工手动填写。

## 八步对照

| 顺序 | 项目 | 记录边界 |
| --- | --- | --- |
| 1 | 风格 | 当前视觉表达、顾客希望的感觉及最终选择 |
| 2 | 人物适配 | 可见曲直与视觉量感、现场补充条件；不从照片推断内在性格 |
| 3 | 长度 | 当前长度、目标落点与需要保留的生活功能 |
| 4 | 发型特点 | 目标轮廓、体积、重量与区域任务 |
| 5 | 层次 | 重量和支撑的调整，表层覆盖与连接 |
| 6 | 刘海 | 方向、边缘、长短、厚薄、露眼程度和脸周连接 |
| 7 | 卷度 | C/S视觉曲线、质感、分布及尚未确认的工艺条件 |
| 8 | 打理 | 顾客可以完成的手法、所需时间与后续维护 |

整体轮廓和发根毛流方向位于八步之前，分别呈现初始判断与优化方案。每一步均展示初始判断、优化方案和调整理由；未确认的信息保持待补，不填成已完成事实。

## 六区执行

八步说明设计方向和理由；六区紧接八步，把方向落到具体位置。各区使用相同的四项：当前问题、目标、具体怎么做、完成核对点。可以先记录已确认区域，再随讨论追加，空白不代表“无需处理”或“已经完成”。

| 区域 | 主要核对内容 | 数据键 |
| --- | --- | --- |
| 刘海区 | 额前风格、目标流向、上下层走向与支撑 | `bangs` |
| 顶区 | 高度支撑、主要纹理、蓬松高度与卷束表现 | `top` |
| 耳前区 | 脸周修饰、流向衔接、落点与刘海连接 | `ear_front` |
| 耳后区 | 侧后转角、上下连接、保留长度与收紧方向 | `ear_back` |
| 中区 | 侧向宽度、主体过渡、重量与上下衔接 | `middle` |
| 底区 | 后颈轮廓、底线重量、收紧或留长 | `bottom` |

四项内部键分别为 `issue`、`target`、`actions`、`check`，在版本顶层 `execution` 下保存。观察不明确、工艺未确认或尚未验收时保持待补，不从完成照片反推出提升角、药剂、温度或其他实际操作参数。

发质分析表原有烫发参数采用头顶、枕骨、两侧、刘海、后颈五区。它与这套六区的定义不同，旧数据保留旧格式，不改名冒充六区，不自动把一项拆给多个区域。新设计使用独立六区执行，与原烫染实操记录各司其职。

## 十大流程与完成复盘

十大流程是全过程参照，在版本顶层 `process` 记录：打理与质感、造型方式、风格与感觉、上药位置、卷杠方法、排杠方向、卷度与控卷、打薄与空间、设计提案、技术与层次。按本次剪、烫、染、造型的实际项目选填，不要求每位顾客机械填满，也不按风格词自动生成化学或设备参数。

完成复盘在版本顶层 `review` 记录已达成（`achieved`）、待调整（`pending`）、下次重点（`next`），结合实际完成照片对照八步目标和六区核对点。待调整项可以保留到后续回访，不把未取得的洗后反馈或顾客满意度填成已知结果。

旧版本没有上述三个对象时按未记录处理，不能根据旧八步或旧五区自行补造历史。每次新增保存包含当时已知的完整内容；只改变八步以外的执行或复盘，也必须保留为新的不可变快照。

## 照片与历史

- 原始照片和完成效果在同页直接展示已上传的各角度，参考图另行标注；点击仅用于放大原图。
- 尚未上传完成照时保留明确空状态；同一次服务补传新的角度后继续追加保存，不等待凑满角度才归档。
- 上传保留原文件字节，不把压缩预览冒充原图；文件摘要用于回读核对。
- 每次保存记录操作人、来源、时间、服务日期和当次状态。
- 初始判断、优化中、方案确认、服务完成和回访均为独立版本。
- 在当前版本移出一张照片不会删除旧版本对该照片的引用。
- 新一次到店增加服务记录；同一次服务继续调整增加版本。

## ChatGPT 协作

发型师提供预约日期和时间后，通过预约文字信息和稳定客户编号定位档案。照片用于发型分析，不用于确认顾客身份。

现场沟通可先按已明确的门店、发型师和服务日期读取预约，以当前时段排序候选。时间接近只用于候选排序；同一时段有多位顾客时，列出预约时间、姓名和项目，供发型师用序号或姓名选择。选定后沿用本次服务上下文，避免重复确认；未核对的候选不写入顾客档案。先交流轮廓、发根毛流和关键设计建议，再补齐八步、六区与归档。收到的完成角度可先同步，后续照片继续追加。

ChatGPT 保存原始判断与后续讨论，不把现场无关闲聊整理入档。设计摘要、八步对照、调整理由、六区执行、十大流程选填、完成复盘和原始图片通过受保护的导入流程追加到同一结构；来源显示为 ChatGPT 协作。员工手填使用同一套字段。ChatGPT 档案链接可作为来源保留，链接本身不授予其他员工访问权限。

导入流程见 [受保护导入工具](customer-design-import.md)。客户资料、照片、短期令牌与导入进度必须保存在仓库之外，不能进入公开 Git 历史。

## 保存与冲突

保存以服务记录的最新版本作为并发前提。若其他人已保存新版本，保留当前草稿和已选照片，先读取新记录并核对，再由员工保存下一版。网络返回不明确时不自动重复写入；恢复时沿用同一请求标识，避免重复版本或重复照片。

每个新保存快照应明确携带六区执行、十大流程和复盘对象，包括经确认应为空的 `{}`。旧客户端省略某对象，而最新记录该对象已有内容时，服务端拒绝本次新保存并返回升级提示，避免无意清掉新字段。原草稿和已选照片保留，员工可在安全时机更新后继续，不强制刷新；已经成功的旧请求仍可按原 UUID 幂等重放。

设计写入必须核对实际顾客、门店及预约关联。“全部门店”仅是读取范围，不授予跨门店写入权限。原有预约备注、套餐、消费记录和同步规则保持各自用途，设计档案不写成消费或烫染诊断记录。

## 发布验证

发布前使用模拟顾客验证照片、八步对照、六区执行、十大流程选填、完成复盘、员工填写、旧格式、历史版本、并发、失败恢复和跨门店拒绝。按兼容顺序部署新增数据库对象、受保护接口和员工端静态资源，通过仓库发布检查后核对线上版本。

真实顾客档案导入属于独立的数据操作，完成后核对顾客编号、预约、版本数量、来源、状态和原始照片摘要。代码发布不自动更改预约状态、消费或其他门店数据，也不强制刷新正在工作的员工。
